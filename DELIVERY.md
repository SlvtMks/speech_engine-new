# Инструкция по передаче проекта заказчику

## Что передать заказчику

### 1. Исходный код

**Вариант A: Git-репозиторий (рекомендуется)**

Создайте репозиторий на GitHub/GitLab/Bitbucket и передайте ссылку:

```bash
# Инициализация git (если еще не сделано)
git init
git add .
git commit -m "Initial commit: Speech Engine STT/TTS"

# Создайте репозиторий на GitHub/GitLab и выполните:
git remote add origin <URL_репозитория>
git push -u origin main
```

**Вариант B: ZIP-архив**

Создайте архив со всей структурой проекта:
- Включите все файлы из `speech_engine/`
- Включите `requirements.txt`, `README.md`, `LICENSE`, `LICENSES.md`
- Исключите: `.venv/`, `__pycache__/`, `*.pyc`, `.git/` (если есть)

### 2. Документация

Убедитесь, что переданы:
- ✅ `README.md` — полная инструкция по установке и использованию
- ✅ `LICENSES.md` — перечень всех лицензий зависимостей и моделей
- ✅ `LICENSE` — лицензия прикладного кода (MIT)

### 3. Дополнительные материалы (опционально)

- Примеры использования (скриншоты командной строки)
- Тестовые аудиофайлы (если есть)
- Краткое описание решения (1-2 страницы)

## Структура передачи

### Минимальный набор файлов:

```
speech-engine/
├── LICENSE              # Лицензия прикладного кода
├── LICENSES.md          # Перечень лицензий зависимостей
├── README.md            # Основная документация
├── requirements.txt     # Зависимости Python
└── speech_engine/       # Исходный код
    ├── __init__.py
    ├── audio.py
    ├── stt.py
    ├── tts.py
    └── cli.py
```

### Что НЕ передавать:

- ❌ `.venv/` — виртуальное окружение (заказчик создаст своё)
- ❌ `__pycache__/` — кэш Python
- ❌ `*.pyc` — скомпилированные файлы
- ❌ `.git/` — история git (если передаёте архив)
- ❌ Модели машинного обучения (скачиваются автоматически)

## Рекомендуемый формат передачи (2026)

### 1. Git-репозиторий (лучший вариант)

**Преимущества:**
- Версионирование кода
- История изменений
- Легко обновлять и поддерживать
- Стандартная практика в индустрии

**Платформы:**
- GitHub (самая популярная)
- GitLab (хорошо для корпоративных проектов)
- Bitbucket (альтернатива)

**Что передать:**
- Ссылку на репозиторий
- Доступ (если приватный репозиторий)
- Краткую инструкцию по клонированию

### 2. ZIP-архив (если Git недоступен)

**Что включить:**
- Весь исходный код
- Документацию
- `requirements.txt`

**Что исключить:**
- Виртуальное окружение
- Кэш Python
- Временные файлы

**Создание архива:**
```bash
# Windows PowerShell
Compress-Archive -Path speech-engine -DestinationPath speech-engine.zip -Exclude @('*.pyc', '__pycache__', '.venv', '.git')

# Linux/Mac
zip -r speech-engine.zip speech-engine -x "*.pyc" "__pycache__/*" ".venv/*" ".git/*"
```

### 3. Docker-контейнер (если требуется изоляция)

**Преимущества:**
- Гарантированная работоспособность
- Не зависит от окружения заказчика
- Легко развернуть

**Недостатки:**
- Требует Docker у заказчика
- Большой размер образа

## Инструкция для заказчика

### Быстрый старт

1. **Клонирование репозитория:**
```bash
git clone <URL_репозитория>
cd speech-engine
```

2. **Установка зависимостей:**
```bash
pip install -r requirements.txt
```

3. **Установка ffmpeg:**
- Windows: скачать с https://ffmpeg.org/ и добавить в PATH
- Linux: `sudo apt install ffmpeg`

4. **Первый запуск:**
```bash
python -m speech_engine.cli stt test.wav --lang auto
```

### Проверка лицензий

Заказчик может проверить все лицензии в файле `LICENSES.md`, который содержит:
- Полный перечень всех зависимостей
- Лицензии всех моделей
- Ссылки на источники

## Дополнительные рекомендации

### Если передаёте через Git:

1. **Создайте `.gitignore`:**
```
__pycache__/
*.pyc
*.pyo
*.pyd
.Python
.venv/
venv/
env/
*.wav
*.mp3
dist/
build/
*.spec
```

2. **Добавьте теги версий:**
```bash
git tag -a v1.0.0 -m "Initial release"
git push origin v1.0.0
```

### Если передаёте архив:

1. **Название архива:** `speech-engine-v1.0.0-YYYY-MM-DD.zip`
2. **Включите файл `INSTALL.txt`** с краткой инструкцией
3. **Проверьте размер архива** (должен быть небольшим, без моделей)

### Для корпоративных заказчиков:

1. **Подготовьте презентацию** (PDF) с описанием решения
2. **Создайте видео-инструкцию** по установке и использованию
3. **Подготовьте ответы на частые вопросы** (FAQ)
4. **Укажите контакты** для технической поддержки
